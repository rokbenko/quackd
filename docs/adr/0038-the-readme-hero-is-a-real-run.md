# ADR-0038: The README hero is a recording of a real run

**Status:** accepted · **Date:** 2026-09-17 · Supersedes [ADR-0013](0013-hero-gif.md)

## Context

Every hero this project has had was a simulator recording driven by the scripted pilot, for the
reason [ADR-0013](0013-hero-gif.md) gives: there was no key on the machine that built it, and
tests must never touch the network. `docs/assets/hero.gif` was the cartoon, then
`docs/assets/quackd-on-off.gif` was the same argument in MuJoCo, one duck with quackd and one
without.

On 2026-09-15 an SO-101 follower arm ran quackd for an afternoon, twelve `--goal` runs piloted
by OpenAI's `gpt-6-astra`, and the last of them was filmed on a phone. That recording answers
the question the rendered pair was arguing about, and answers it with a real robot: you type a
sentence, an LLM picks the arm's own verbs one at a time, and the arm waves. A reader who
sees a rendered duck first has to be told that the real thing works. A reader who sees the arm
does not.

The obstacle was size. This repository caps every file under `docs/assets` at 2048 KB, in the
`check-added-large-files` hook, in `hero3d.py` and in a test that reads the two and holds them
together. A render spends bytes on what moved and nothing on the rest, which is why the MuJoCo
pair fits in 1441 KB at 579 pixels wide. A photograph of a lab spends them on every pixel of
every frame: the same nine seconds fits under 2048 KB only at 320 pixels, or by throwing away
two thirds of the wave. Neither is a hero.

## Decision

- **`docs/assets/lerobot.gif` is the README hero**: the run of 2026-09-15, filmed on a phone,
  shown at ten times speed, cut by [`lerobot_hero.py`](../assets/lerobot_hero.py) at 640
  pixels, 10 frames a second, 128 colours.
- **It is the one file allowed over the general cap, and it carries a cap of its own.** The
  hook names it in an `exclude`, the script names `HERO_MAX_BYTES`, and
  `tests/test_pypi_readme.py` asserts that the exclude names exactly this file, that the file
  is genuinely over the general cap (so the exception is not left behind once it stops being
  needed), and that it is under its own number. Everything else keeps the 2048 KB cap.
- **`quackd-on-off.gif` stays in the README**, moved under *No robot yet? Try it in 60
  seconds*, where it is now arguing for the simulator rather than for the project. It is still
  the one file here under CC BY-NC-SA, and its caption says so where it now sits.
- **The recording is not reproducible from this repository, and the catalogue says so.** The
  phone video and the run's frames and transcript live on the machine that drove the arm. The
  script that cuts them is committed, the inputs are not, which is the honest shape for a
  recording of a real robot and is different from every other asset here.

## Consequences

- A clone is about 8 MB heavier, once, and the README page carries that on first load. That is
  the price of leading with the real thing, and it was a deliberate trade rather than an
  oversight.
- The hero can no longer be regenerated by a script. Replacing it means an arm, an LLM and an
  afternoon, so the next better clip comes from somebody with hardware rather than from a
  command.
- Every sentence that said the hero was the scripted pilot, or that no recording here had an
  LLM in it, became false and was corrected with this change. `docs/assets/README.md` now
  distinguishes *simulator* recordings, which are all scripted, from the two that are not.
- [ADR-0013](0013-hero-gif.md)'s open item, regenerating the hero with a real LLM, is closed
  by a different route than it expected: not a keyed `quackd record` in a simulator, but a
  camera pointed at a bench. A real LLM recording in either simulator is still open, and is
  still listed under *Help wanted*.
